# Data Modeler 샘플

데이터 모델링 앱의 프로젝트 파일(`.dmodel.json`) 샘플입니다.
DevVault 통합 앱의 **Data Modeler** 앱, 또는 **DevVault Modeler** 단독 제품에서 엽니다.

한국식 데이터 표준화(단어 → 용어 → 도메인 → 엔티티 → DDL)를 따르므로,
샘플에는 ERD뿐 아니라 **단어사전·도메인·용어사전이 함께** 들어 있습니다.

## 여는 법

1. 파일명을 클릭 → 우측 상단 **Download raw file**
2. Data Modeler에서 `Ctrl+O` → 내려받은 파일 선택 (창에 끌어다 놓아도 됩니다)

## 열어본 뒤 해볼 것

- **엔티티에 속성을 추가**해 봅니다. 컬럼명을 타이핑하는 칸이 없습니다 —
  **용어를 고르면** 영문 컬럼명과 물리 타입이 자동으로 채워집니다.
  (예: 단어 `고객(CUST)` + `명(NM)` → 용어 `고객명` → 컬럼 `CUST_NM`)
- 타입도 직접 지정하지 않습니다. 용어에 매핑된 **도메인**이 타입을 결정합니다.
  도메인의 길이를 바꾸면 그 도메인을 쓰는 모든 컬럼이 함께 바뀝니다.
- **DDL 내보내기**로 PostgreSQL `CREATE TABLE` 스크립트를 뽑아 봅니다.
  한글 엔티티명·용어명은 `COMMENT ON`으로 나갑니다.

### 쇼핑몰.sql — 반대 방향(SQL 가져오기)

기존 DB의 DDL을 넣었을 때 어디까지 복원되는지 보는 샘플입니다.

- `COMMENT`의 한글이 엔티티명/용어명으로 복원됩니다.
- 단어사전이 비어 있으면 컬럼명 토큰(`CUST`/`NO`/`NM` …)은 **미매칭**으로 보고됩니다.
  → 빈 모델에서 한 번, 위 샘플처럼 단어사전이 채워진 상태에서 한 번 가져와 비교해 보면
  단어사전이 무엇을 하는지 바로 보입니다.
- 단독 PK 인라인 / 복합 PK 한 줄 / 인라인 `REFERENCES` + `ALTER` FK 를 모두 포함합니다.

## 파일 형식 메모

- 한 파일에 `words`(단어) · `domains`(도메인) · `terms`(용어) · `entities` · `relationships` ·
  `tableGroups` · `views`가 모두 들어가는 **단일 프로젝트 파일**입니다(별도 DB 없음).
- 컬럼명·타입은 저장하지 않고 용어/도메인에서 파생합니다. 표준을 어길 수 있는 경로 자체가 없습니다.
- JSON이라 git에 넣고 diff를 읽을 수 있습니다.
