# WBS 샘플

작업분해구조(WBS) + 간트 타임라인 앱의 프로젝트 파일(`.wbs.json`) 샘플입니다.
DevVault 통합 앱의 **WBS** 앱에서 엽니다.

## 샘플

| 파일 | 규모 | 무엇을 보여주는가 |
|---|---|---|
| [사내홈페이지리뉴얼.wbs.json](samples/사내홈페이지리뉴얼.wbs.json) | 작업 13 · 의존 8 | **입문용.** 2수준 분해, FS 의존, 마일스톤. 달력은 기본값(주5일, 휴일 없음) |
| [모바일앱v2출시.wbs.json](samples/모바일앱v2출시.wbs.json) | 작업 25 · 의존 16 | **기능 전시용.** 3수준 분해, FS/SS/FF/SF 4종 의존, lag와 lead(음수 lag), 사내 휴무일 달력, 고정 일정(manual), 차단 상태, 일정 미지정 리프(검증 경고), 마일스톤 2개 |

처음이라면 `사내홈페이지리뉴얼`부터 열어보길 권합니다.

## 여는 법

1. 파일명을 클릭 → 우측 상단 **Download raw file**
2. DevVault에서 **WBS** 앱을 열고 `Ctrl+O` → 내려받은 파일 선택
   (창에 끌어다 놓아도 됩니다)

## 열어본 뒤 해볼 것

- 간트 바를 **드래그**해 시작일을, **오른쪽 끝을 드래그**해 기간을 바꿔봅니다.
  선행 작업을 밀면 후행 작업이 의존 관계를 따라 함께 밀립니다.
- 행에서 `Enter`(형제 추가) · `Shift+Enter`(하위 추가) · `Tab`/`Shift+Tab`(수준 변경)으로
  트리를 편집합니다. WBS 코드(`1.2.3`)는 위치에서 자동으로 다시 매겨집니다.
- 요약 행의 일정·공수·진행률은 **직접 입력하지 않습니다.** 하위 작업에서 자동 롤업됩니다.
- `모바일앱v2출시`는 검증 경고가 일부러 남아 있습니다. **검증 패널**을 열어
  어떤 항목이 잡히는지 확인해 보세요.

## 파일 형식 메모

- 저장되는 것: `tasks[]`(트리 구조 + 리프 값), `links[]`(의존), `calendar`(근무일·휴일)
- 저장되지 않는 것(파생): WBS 코드, 요약 행의 일정·공수·진행률, 종료일
- 기간은 **종료일 포함** 영업일 기준입니다(`기간 1` = 당일 종료)
- 2-스페이스 들여쓰기 JSON이라 git에 넣고 diff를 읽을 수 있습니다
